# EGAS · Проверка расходов УК

Сервис для проверки расходов управляющей компании по отчёту, актам, договорам и другим документам за выбранный период.

EGAS сопоставляет суммы и условия, показывает расхождения с цитатами из источников и помогает подготовить запрос к УК.

[Открыть сервис](https://egas-expense-audit.egas-expense-audit.workers.dev/) · [OnePager продукта](ONEPAGER.md)

## Статус

Работающий прототип. Готовится к проверке на реальных комплектах документов. Точность, экономия времени и коммерческая модель пока проверяются.

## Для кого

Для собственников коммерческой недвижимости и сотрудников, контролирующих расходы на управление объектом.

## Как пользоваться

1. Выберите период проверки.
2. Добавьте отчёт УК, акты, договоры и прочие документы. Можно прикрепить файлы или вставить текст. Любую категорию можно пропустить.
3. Запустите разбор комплекта.
4. Проверьте выделенные расходы и извлечённые значения. При необходимости внесите уточнения.
5. Откройте замечания, сверьте источники и отредактируйте запрос к УК.

## Что показывает сервис

- Расходы, выделенные из документов.
- Сопоставление сумм, ставок и других условий.
- Арифметические расхождения и недостающие основания.
- Цитаты, на которых основаны замечания.
- Запросы к УК по отдельному замечанию и по всему комплекту.

## Поддерживаемые документы

PDF с текстовым слоем, XLSX, TXT, CSV и TSV. Максимальный размер файла — 10 МБ. Также доступна вставка текста вручную.

Сканы без текстового слоя нужно предварительно распознать.

## Как устроена проверка

ИИ извлекает сведения из документов. Программные правила проверяют расчёты и сопоставляют значения. Пользователь может проверить источники и исправить извлечённые данные.

## Ограничения

- Результат зависит от полноты комплекта и качества документов.
- Извлечение и сопоставление могут содержать ошибки.
- За один запуск разбирается до 20 расходов; большой комплект может потребовать отдельных проверок.
- Расхождение требует разбирательства и само по себе не подтверждает переплату.
- Автоматическое сохранение проверок между сеансами пока не реализовано.

## Обработка данных

Для разбора используется внешний ИИ-провайдер. Извлечённый текст документов передаётся за пределы устройства пользователя. Перед загрузкой рабочих документов необходимо убедиться, что такая передача разрешена.

Локальная модель пока не реализована.

## Планы развития

1. Сохранение проверок и договоров.
2. Загрузка ответов УК и повторная проверка замечаний.
3. Проверка следующих периодов с учётом действующих договоров.
4. Сравнение расходов с бюджетом.
5. Сопоставление начислений с оплатами и поиск дублей.
6. Общий обзор расходов и открытых вопросов по нескольким объектам.

## Проверка продукта на пилоте

Планируется сравнить сервис с ручной проверкой: измерить время работы, пропущенные расхождения, ошибочные замечания и полезность подготовленных запросов. Отдельно проверить готовность заказчика оплачивать регулярное использование.

## Быстрый запуск

Нужен Node.js 22.13+ (ветка 22) или более новая поддерживаемая версия и npm.

1. Клонируйте репозиторий и перейдите в его папку.
2. Установите зависимости: `npm ci`.
3. Соберите приложение: `npm run build`.
4. Проверьте сборку: `npm test` и `npm run validate`.
5. Запустите: `npm run dev`.
6. Откройте http://127.0.0.1:4173/.

## Реальное извлечение ИИ

Скопируйте `.env.example` в `.env.local`, заполните ключ выбранного провайдера и перезапустите сервер. Не публикуйте ключ. При наличии обоих ключей используется OpenRouter. Модель по умолчанию — `openai/gpt-4.1-mini` для OpenRouter, `gpt-4.1-mini` для OpenAI.

Разбор ИИ запускается пользователем и оплачивается по тарифу провайдера. Тексты документов передаются серверу приложения и далее внешнему провайдеру. Используйте только данные, на такую передачу которых есть разрешение.


## Структура

- `src/audit.mjs` — схема извлечения, проверка цитат и расчёты.
- `worker/index.js` — серверные маршруты и вызов провайдера ИИ.
- `web/` — интерфейс и чтение файлов в браузере.
- `scripts/` — сборка, локальный запуск и проверка артефакта.
- `tests/` — проверки правил и серверных маршрутов без платных ИИ-запросов.

Сборка создаёт единый ESM Worker в `dist/server/index.js`, включая браузерные ресурсы и PDF.js. Минимальный `.openai/hosting.json` сохранён для совместимости формата сборки; привязки к чужому проекту размещения нет. В аккаунте EGAS подключён Cloudflare Workers Builds: изменения в ветке `main` запускают проверки, сборку и публикацию сайта. Команда сборки: `npm run build && npm test && npm run validate`; публикация: `npx wrangler deploy`. При ошибке проверок новая версия не публикуется.

PDF.js (Mozilla Foundation, Apache License 2.0) устанавливается из npm. Его лицензия доступна в работающем приложении по адресу `/vendor/LICENSE`.

## Проверка комплекта за период

Новый запрос использует `mode: period`, `period: YYYY-MM` и `sources` с уникальными id, категориями, именами и полными текстами. Каждый расход возвращает отдельные извлечённые поля. Цитаты проверяются только в указанном источнике, а не во всей категории; для PDF сохраняется ближайший маркер страницы. Начисления с явно другим месяцем не допускаются. Пропущенные категории не блокируют запуск: они ограничивают доступные сравнения. Полнота охвата, применение договоров, подписи и подлинность источников требуют проверки сотрудником. Правила для месячной ставки за м² сохранены; суточные, разовые и другие тарифы не приводятся автоматически.

Переключение расходов сохраняет ручные уточнения и решения. Скачивание и запрос в УК включают весь выделенный комплект. Все файлы и текст остаются только в памяти страницы; постоянное хранение не добавлено.
